# SRM Suite v0.3.0-beta

Android version code: 2. Package ID: `com.srmsuite.app`.

## Changes

- Required server-validated login with expiring sessions, logout, and viewer/editor write authorization.
- Signed-in username and role visible in the header; tap the logo or account label for a left account panel.
- Settings & connection and Logout are in the left panel; Home, Attendance and Scanner stay in the bottom navigation.
- Settings slides in from the left. Fresh installations have a Configure button and no embedded Sheet connection.
- Password visibility toggle, mobile-friendly login focus, useful empty-roster state, and attendance controls above bottom navigation.
- Authentication regression tests and a documented security assessment.

## Backend upgrade required

Deploy the current `apps-script/Code.gs` as a new version of the existing Apps Script web app (authentication protocol 2). Run `setUserPassword` to create accounts. Older anonymous clients cannot access the updated backend.

## Artifacts

- `SRM-Suite-v0.3.0-beta-release-test-signed.apk`: installable release-variant beta signed with the existing debug/testing certificate. This disables Android debugging but is not production signing.
- `SRM-Suite-v0.3.0-beta-debug.apk`: installable, debug-signed test APK. Updates an existing `com.srmsuite.app` beta only when its signing key matches.
- `SRM-Suite-v0.3.0-beta-release-unsigned.apk`: release-variant APK requiring production signing before installation.
- `SRM-Suite-v0.3.0-beta-source.zip`: repository source snapshot, excluding ignored files and local credentials.
- `SHA256SUMS.txt`: checksums for the APKs and source snapshot.

The earlier `org.attendancetracker.app` is a separate app; installing SRM Suite does not migrate its cached or pending records automatically. A matching-package update preserves data. A fresh install starts with connection setup, then login.

## Validation

All 19 tests, the production web build, and Android debug/release APK builds passed. The installable release APK passed signature verification (v2/v3), reports version `0.3.0-beta` / code `2`, and installed successfully on Medium Phone API 37.0. Its release manifest does not enable Android debugging. The build was checked for the saved organization endpoint and API key; neither was embedded.

## Known limitations

This is a prerelease for testing. Password hashing/throttling, spreadsheet formula handling, local cache protection, and development dependencies still require the work described in `SECURITY_ASSESSMENT.md`. Do not treat this beta as a production security release.
